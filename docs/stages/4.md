# Phase 4 — Reconciliation ledger and public ops

*Completed 2026-08-19. Evidence: [`evidence/2026-08-19-first-reconciliation.md`](../../evidence/2026-08-19-first-reconciliation.md).*

The headline claim, proven end to end against a real lake for the first time:
**every 15-minute window reconciles exactly against generator ground truth.**

```
windows  events_exact  bronze_deduped  manifest_events  corrupt  dup_extra  late
    523           523            4151             4155        4         92     85
```

## The arithmetic closes

```
manifest events            4,155
  − corrupt (quarantined)      4
  = deduped bronze         4,151   ✓ matches Athena
  + duplicate extra copies    92
  = raw bronze             4,243   ✓ matches Athena
```

Every row is attributable to a disorder class injected at a declared rate. That
is the difference the project exists to demonstrate: not "the counts look about
right", but "the counts are exactly what they must be, and here is why each one
differs from a naive count."

**523 of 523 exact** is a stronger claim than an aggregate match, and
deliberately so. A total that agrees can hide two windows that are wrong in
opposite directions; a per-window ledger cannot.

## The status page

`docs/status/index.html`, built by `tools/build_status_page.py`, published at
[steve27m.github.io/factorystream/status/](https://steve27m.github.io/factorystream/status/).

Self-contained by design — no CDN, no runtime fetch, no framework. A snapshot of
a query result should still open in five years, when whatever it depended on has
moved.

## Cost, and the duty cycle

`COSTS.md` carries the arithmetic rather than a number, so a reader can check it
instead of trusting it. Nothing in the stack has an idle cost, which is what
makes leaving it standing safe.

**No 24/7 streaming.** The duty cycle is a documented cost decision and a
binding Non-Goal, not a limitation being hidden. The broker runs when a run
runs.

## What is not done

**Scheduled duty-cycle runs.** The spec asks for scheduling; there is no cron
and no scheduled workflow. Runs are manual today, and the status page therefore
reflects the last manual run rather than a heartbeat.

Adding a schedule is cheap. It is listed here rather than quietly omitted
because a status page that looks live and is not is worse than one that is
plainly dated.
