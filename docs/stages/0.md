## The one item that could not wait

**CUR has no backfill.** Billing detail exists only from the day the report is
switched on, so every day it is not enabled is a day of cost attribution that
can never be recovered. That is why it is in Phase 0 rather than in the cost
phase where it would more naturally belong.

`RESOURCES` schema rather than the default, for the same reason: it gives
per-resource-id attribution, which is the difference between "S3 cost $4" and
"*this bucket* cost $4."

## Guardrails for two projects, deliberately

This module is account-level and covers **WearWatch as well**. Budgets, the CUR,
and the shared `plant-platform` Athena workgroup with its per-query scan cap all
apply to both. WearWatch's `docs/COSTS.md` delegates here explicitly rather than
duplicating them: two Terraform states both claiming the same budget is a fight,
not a safety net.

The scan cap is the guardrail that does the most work. It is roughly 40× the
entire lake, so a query that trips it is a query that is wrong — a `select *`
across every partition, not a legitimately large scan.

## No OIDC secret, and no long-lived key

CI authenticates by assuming the deploy role through GitHub's OIDC provider.
There is no AWS access key anywhere in either repository, which is why the
`.gitignore` patterns for credential files exist as a reflex-blocker rather than
as protection for something real.
