# Phase 1 — Generator and manifest

*Completed 2026-08-19.*

The generator is the whole thesis. Everything this project claims about
correctness rests on one property: **it knows exactly what it emitted**, so the
warehouse can be graded against known truth rather than self-checked.

## One run, seed 42

```
seed 42
  clean events         4,155
  published records    4,247
  windows                523  (8 machines)
  cycles / defects     3,853 / 84
  injected:
    late                      85
    duplicate copies          92 across 52 events
    out-of-order             140
    schema v2              2,078
    corrupt                    4
    skewed machines       ['MW1-B-01', 'MW1-A-01']
```

Note the two totals. **4,155 clean events, 4,247 published records** — the
difference is 92 duplicate copies. Both numbers matter downstream and confusing
them is how a reconciliation quietly stops meaning anything.

## The disorder is the product

A generator that emitted clean events would make late data, duplicates,
ordering and exactly-once handling *untestable*. So each class is injected on
purpose at a configured rate, and each one forces a specific behaviour:

| injected | forces |
|---|---|
| **late** (85) | watermarking, and a late-arrival policy stated rather than implied |
| **duplicates** (92 copies across 52 events) | idempotent dedup that keeps the *earliest* publish |
| **out-of-order** (140) | ordering that cannot rely on arrival sequence |
| **clock skew** (2 machines) | event time and ingest time kept as separate columns |
| **schema v2** (2,078) | a silver layer that conforms two shapes into one |
| **corrupt** (4) | a quarantine path, so bad rows are *counted* rather than dropped |

Every one appears in the reconciliation as a named quantity. **A disorder class
you cannot point to in the arithmetic is a class you have not actually
handled.**

## Determinism, and why the ids are not uuid4

The headline property is that the same seed produces a byte-identical stream and
manifest. `uuid.uuid4()` would break that on every run, so `new_event_id` derives
the id from the seeded RNG and wraps it in `uuid.UUID(hex=...)` — familiar shape,
reproducible bits.

Determinism is what makes the manifest checkable by a third party: they can
regenerate the stream and get the same file.

## The manifest never travels the pipeline

It is written straight to storage. That is the difference between a comparison
against known truth and a self-check — a manifest that arrived through the
broker would share every failure mode of the thing it is grading.

The same reasoning appears in WearWatch, where simulator ground truth bypasses
the telemetry path for identical reasons. Two projects, one rule.

## Windows are computed in event time, skew included

523 windows of 15 minutes across 8 machines, and the window boundary uses the
event time **the machine reported** — including any injected clock skew.

Correcting the skew first would be defensible engineering and would fail the
grading, because the manifest records what the machine said. Grading against a
corrected time the pipeline never saw would mark the pipeline wrong for the
generator's own fiction.
