## The account module went too

`infra/terraform/app/` and `infra/terraform/account/` were both destroyed — 9
and 17 resources respectively.

The account module had been kept out of scope during the acceptance run for a
good reason: it held the budgets and CUR that covered a sibling project which
was still live. Once that project was torn down, the calculation inverted.

**The deciding factor was the OIDC deploy role**, which carried
`AdministratorAccess` and was assumable from two now-public repositories. Its
trust policy was correctly scoped — `repo:Steve27M/factorystream:ref:refs/heads/main`
and five siblings, not a wildcard, so a fork's pull request could never assume
it — but with nothing left to deploy it protected nothing while remaining a
standing path to admin. A guardrail with no asset behind it is only a surface.

## The permanent consequence, stated

**The Cost and Usage Report has no backfill.** Destroying it does not lose the
report data already written to S3 — but that bucket went with it, and any future
period before a new CUR is enabled is a hole that no later apply fills.

That was acceptable here because the account is empty: there is no spend left to
attribute. It would not have been acceptable a day earlier.

## Reproducible without any of it

The whole pipeline runs from `make generate` onward with no AWS account, and the
warehouse builds on DuckDB over the same parquet the consumer writes. The
523/523 reconciliation is checkable by anyone who clones the repo.
